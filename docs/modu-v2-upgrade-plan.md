# 墨读 v2 增量升级计划

## 变更边界

| 类别 | 内容 |
| --- | --- |
| 保留 | 用户、账户、会话、家长绑定、管理员审核、书架、阅读分页、阅读进度、字号、设置、现有 Netlify 运行链路和旧单词数据 |
| 修改 | 首页信息架构逐步收敛为“单词 / 阅读”；`/k/words` 分阶段切换到新引擎；家长和管理员页面增加 v2 只读/管理视图 |
| 新增 | `modu_vocab_` 增量表、核心 500 词库、平台无关学习引擎、7 词微单元、动态复现、阅读曝光事件、D1/Postgres 仓储适配器 |
| 迁移 | 仅迁移能可靠映射到核心 500 的旧词汇数据；无法确认语义的旧数据继续保留，不猜测、不覆盖 |

## 阶段顺序

1. **审计与基线**：完成旧项目审计、旧库计数、备份和兼容性试迁移。
2. **数据层**：加入增量迁移与 500 词种子，实现仓储契约、D1 适配器和 Postgres 备用适配器，做契约测试。
3. **单词首页**：在现有 `/k/words` 中接入每日 7/14/21/28、今日进度和继续学习入口。
4. **7 词学习流程**：实现初识、熟悉、掌握以及每 7 词保存/停止；核心流程无 JavaScript 可用。
5. **动态复现**：接入学习事件、到期复现和每日上限，保证没有必须清空的复习债务。
6. **阅读联动**：阅读页记录低成本词汇曝光，在后续微单元中优先复现阅读中遇到的词。
7. **管理能力**：增加核心词库、学习状态和阅读联动的管理员视图，不替换既有后台。
8. **双平台发布准备**：Cloudflare Workers + D1 为首选；Netlify Functions + 现有存储继续作为备用，并保留 Postgres 接口。

每个阶段均先运行单元测试、迁移重入测试、旧表计数回归和 Kindle 手工流程检查。只有本阶段通过后才进入下一阶段；真实部署必须等待用户明确指令。

## 数据安全规则

- 所有迁移仅允许 `CREATE TABLE IF NOT EXISTS`、`CREATE INDEX IF NOT EXISTS` 和可重入 upsert。
- 不执行 `DROP`、`TRUNCATE`，不删除旧表、旧用户、旧阅读进度或旧学习记录。
- 在真实本地库应用 v2 迁移前创建 SQLite 一致性备份。
- 生产 D1 迁移遵循本地测试、远程 dry-run、显式确认、正式执行的顺序。
- 平台密钥只存在环境变量或平台 Secret 中，永不写入仓库。
